При объявлении какого-либо скрипта на Destroy (как компонента) приостанавливается выполнение его жизненных функций (если сразу после Awake его начинать удалять, то до Start не дойдёт).
Стоит отметить, что удаление будет только в конце "следующего кадра", но работает это странно. Окончательный вызов OnDestroyed происходит после вызовов Start других скриптов, но
при этом сам метод Start для удаляемого компонента вызван не будет, так что этот "следующий кадр" довольно растянут во времени (по сути время от Awake через Start до OnDestroyed).

Также замечено странное поведение компонентов:
    если после пометки на удаление одного компонента скрипта привязать к объекту другой, то у него отработает сразу Awake, а после и Start (при этом метод Start для помеченного на
    удаление, как и отмечалось ранее, вызван не будет). В методе Start если получить ID компонента через this и gameObject.GetComponent, то у них выведутся разные ID, видимо,
    старый компонент, получаемый через gameObject.GetComponent, имеет какой-то приоритет над новым (с учётом, конечно же, что и первый и второй компонент наследуются от того компонента,
    который мы пытаемся получить через GetComponent)

        Debug.Log(this.GetInstanceID());
        Debug.Log(gameObject.GetComponent<Equipment>().GetInstanceID());
                --- Вызовы выше выдадут разные значения в описанной ситуации! ---

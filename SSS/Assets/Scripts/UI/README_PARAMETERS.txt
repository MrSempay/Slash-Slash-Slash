Был создан вручную механизм тумблера, находится в скрипте ToggleFixed. Суть его работы следующая:

ВИЗУАЛИЗАЦИЯ

	Экземпляр класса тумблера обладает двумя спрайтами: спрайт для вжатого и отжатого состояния. Инициализируются спрайты в методе Awake, причём если
у тумблера проставлен флаг justCheckMarck в true - значит будут подгружены спрайты по умолчанию (пустой квадратик для отжатого и квадратик с галочкой для вжатого состояния), 
если флаг проставлен в false, значит используются кастомные спрайты. Спрайты должны быть в формате .png/.jpg и иметь имя по следующему шаблону: name + "Toggled"
для вжатого спрайта и name + "Untoggled" для отжатого спрайта. Все спрайты (равно как и спрайты для _justCheckMarck) находятся в папке по пути C.DK.PathFolderImagesForToggles.

	При первом срабатывании Awake и при каждом изменении состояния тумблера вызывается функция ControllVisualizationToggle(bool) - в качестве параметра передаётся текущее
состояние тумблера. Разберём данную функцию:

- при входе в неё сразу проверяем состояние тумблера, если он не вжат, то мы проверяем, был ли найден при инициализации (в Awake) спрайт для отжатого состояния. Если был
найден, то тогда устанавливаем данный спрайт как спрайт для тумблера. При этом в любом случае (был спрайт изменён или нет) мы меняем цвет нашего тумблера на указанный
(пока что в виде магической константы указан белый цвет, то есть цвет в данной версии скрипта для отжатого состояния всегда меняется в стандартный для спрайта).

- если тумблер таки был вжат, то мы проверяем, был ли найден при инициализации (в Awake) спрайт для вжатого состояния. Если да, то меняем текущий спрайт тумблера на тот,
который был найден в Awake. Если нет, то меняем цвет тумблера (в инспекторе можно выбрать, каков должен быть цвет вжатой кнопки. Можно и не менять, оставив белый по умолчанию).
Также, раз у нас не нашлось спрайта для вжатого тумблера, проверяем, нашелся ли спрайт для отжатого. Если он был найден (в Awake ещё), то ставим его. Если нет такого, то ничего
не делаем (у тумблера будет какой-то свой спрайт по умолчанию, вроде этот спрайт аналогичен для отжатого спрайта _justCheckMarck, при вжатии/отжатии будет просто меняться его цвет).

ЛОГИКА

	В методе Awake задаём имя вызываемой данным тумблером функции по шаблону "Trigger" + name, контроль наличия данной функции осуществляется в EventBas, далее проверяем, 
проставлена ли галка _shouldBeToggledAtStart (меняется в инспекторе, по умолчанию установлено в false), если это так, то мы устанавливаем свойство
IsToggled в true и прерываем метод Awake (дальше у нас в Awake идёт метод ControllVisualizationToggle, но его выполнять не нужно, так как это делается уже в рамках свойства).

	Свойство IsToggled булево, в самом свойстве сначала вызываем ControllVisualizationToggle, далее создаём массив параметров из двух элементов, значение свойства (value)
и компонента RectTransform нашего объекта тумблера (именно объекта тумблера, а не поля параметра с тумблером).

	Далее мы проверяем, является ли текущее значение свойства true, если это так, то проверяем, является ли данный тумблер экземпляром класса ToggleFixedOneWay, который наследуется
от ToggleFixed (вся разница между ними в том, что тумблер первого класса можно кликом только вжать, но не отжать), если это так, то пытаемся получить компонент ToggleGroup
у родительского объекта для тумблера, если этот компонент не равен null (то есть это тумблер для вжатия в одну сторону и он находится в какой-то группе тумблеров), то для
объекта группы мы:

- вызываем метод Awake (чтоб всё в нём инициализировалось пред тем, как дальше с ним работать)
- вызываем метод ControllOnlyOneToggledToggle (не буду расписывать его логику, суть работы: отжимает предыдущий вжатый тумблер, оставляя вжатым только один текущий)
- вызываем метод InvokeGroupFunction, передаём в качестве параметра экземпляр скрипта ToggleFixedOneWay, эта функция делает что-то характерное для данной группы тумблеров

	В любом случае (даже если текущее значение свойства IsToggled равно false), вызываем функию CallFunctionByName(_nameInvokingFunction, EventBus.Instance, parameters)
статического класса StaticClassForAdditionalFunctions. Данная функция вызовет функцию с именем _nameInvokingFunction у объекта EventBus.Instance с параметрами parameters.
Есть ли функция с таким именем и параметрами у такого объекта оставляем на котроль самой функции CallFunctionByName. Если такой функции не будет обнаружено, то выведется
предупредительное сообщение, но это штатная ситуация.

На данный момент подразуемвается, что в группе тумблеров могут быть только тумблеры ToggleFixedOneWay.


																				Поле со слайдером

ЛОГИКА

	Сам объект слайдера используется стандартный, предоставляемый Unity. Параметр по сути объединяет слайдер и текстовую надпись, находящуюся сверху от него. Слайдер при любом
изменении положения ползунка вызывает функцию ValueOfSliderWasChanged, в которой происходит присвоение свойству CurrentValue значение положения ползунка слайдера.
В методе Awake инициализируем имя вызываемой функции по шаблону: _nameInvokingFunction = C.Prefixes.PrefixTrigger + selfName, а также вызывается функция ValueOfSliderWasChanged для
Первичного применения значения данного параметра (используется, например, при загрузке сохранённых настроек).

	В свойстве CurrentValue происходит актуализация положения ползунка в зависимости от свойства (ибо у нас может меняться свойство CurrentValue напрямую из других скриптов,
а не только через функцию ValueOfSliderWasChanged, в таком случае нужно синхронизировать значение свойства и визуализацию ползунка) _slider.value = value. Создаём массив параметров,
в котором также будут два элмемента: float для текущего значения свойства (положения ползнука) и RectTransform параметра слайдера (НЕ САМОГО СЛАЙДЕРА ТЕПЕРЬ, А УЖЕ ПАРАМЕТРА).
Также вызывается функция, привязанная к данному параметру через CallFunctionByName(_nameInvokingFunction, EventBus.Instance, parameters), более подробно этот процесс расписан в пункте
по тумблеру выше


																Поле с кнопкой, которая меняет своё значение по нажатию

ЛОГИКА

	Представляет из себя кнопку с текстом. Основной параметр - listChosing, заполняется из скрипта StaticClassForAdditionalFunctions при первом входе в метод Awake.
Данный параметр представляет из себя массив перечислений ENUM, доступных для выбора. При нажатии на кнопку вызывается функция OnParameterButtonClick, в которой свойство CurrentValue
устанавливается в значение текущего элемента списка listChosing. Глобальный (для данного экземпляра параметра) счётчик списка увеличивается (то есть при следующем нажатии на кнопку
свойство CurrentValue установится в следующий элемент этого списка) на единицу, при достижении конца списка он обнуляется. В свойстве также создаётся массив параметров с двумя элементами:
значение свойства (объект ENUM) и RectTransform ПАРАМЕТРА. Вызывается функция через CallFunctionByName(_nameInvokingFunction, EventBus.Instance, parameters)

ВИЗУАЛИЗАЦИЯ

	Меняется текстовое поле при каждом нажатии кнопки в функции OnParameterButtonClick через свойство CurrentTextValue на строковое представление текущего объекта ENUM
